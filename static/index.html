kernel98scan

Is this host exposed to the kernel TCP bug?

CVE-2026-98432 is a use-after-free in the Linux kernel's IPv4 TCP handshake, in every kernel since 4.4. An attacker who can reach any open port may crash the server, and a working remote root exploit has been reported. From the network a patched and an unpatched kernel look the same, so this page shows which Linux distribution a server reveals and whether that distribution has a fixed kernel yet. The real answer comes from the server itself.

The check loads the host's start page the same way a browser does. Nothing else is sent.

The real check runs on the host.

From outside, nobody can tell a patched kernel from an unpatched one. The command-line version reads the running kernel on the machine itself and gives a real verdict: vulnerable, reboot needed or fixed. From outside it also does whole IP ranges, a port scan and every website on the same server. One Python file, nothing to install.

# on the host you want to check:
curl -LO https://github.com/akaihigurashi/kernel98scan/releases/latest/download/kernel98scan.py
python3 kernel98scan.py --on-host

# or from outside (distribution only):
python3 kernel98scan.py 203.0.113.0/24

# only check systems you're allowed to test

How it works

We load the host's start page and read the Server header to tell which Linux distribution it is, then show whether that distribution has released a fixed kernel. We never try to trigger the bug.

Why it never says "vulnerable" or "patched"

The kernel can't be seen from the network. The banner shows the web server's distribution, and behind a reverse proxy or inside a container the kernel belongs to another machine. So the most this page can say is "possibly vulnerable": no fixed kernel exists yet, or one exists and you have to install it and reboot. --on-host on the server is the final word.

Rules of use

Only check hosts you own or have permission to check.

Privacy

For every check we store the time, your IP address, your browser's name and the checked address, to prevent and investigate abuse. These records are deleted after 30 days, unless they are needed to report or investigate a specific case of misuse. No cookies, no tracking, no third-party content.

kernel98scan is part of shouldipanic.ch, open-source checks for current web vulnerabilities.

Why 98?

The bug is CVE-2026-98432, a use-after-free deep in the kernel's TCP code. We took the 98 and gave the scanner a little silicon of its own. The real work, as ever, happens in the kernel.
